# Juiz - Personal Assistant · 设计 V3.1

> 版本：V3.1，2026-09-29。在 V2《手机原生 AI 助手：复用 ChatGPT Work 的轻量架构》基础上细化，并加入实现层设计。
> V3.1 新增：情绪滤网、深夜代办、选句代答、执行方（云端 / ChatGPT App / 电脑 Codex）、伙伴 Juiz、音频测试台，以及真机前的模拟器验证结果。
> V2 的产品目标、边界和"不虚构接口"的要求全部保留。本文新增的每个平台接口都注明了核对来源；尚未在真机验证的部分单独标注。

## 0. 一句话

装在主人手机上的开源助理：别人打主人的原号码，手机按规则接起，由 AI 以披露过身份的授权音色应答；需要办事时整理成任务卡交给 ChatGPT Work，主人审批后执行，全过程留下可离线阅读、可校验的档案。

| 11 | **预合成常用语 + 延迟预算** | 电话体验的核心是"对方说完到听见回应"的时间 |

| 14 | **情绪滤网**：本人接听，Juiz 只改变本人听到的内容 | 上班族最怕的"被骂"电话：对方确实在和本人说话，不涉及冒充 |

| 16 | **选句代答**：本人从候选回复里选一句（或输入），由合成声音说出 | 不想开口也能回应；每句话都由本人决定 |
| 17 | **执行方分层**：云端大模型（手机直连）/ ChatGPT App / 电脑 Codex | 电话里的小模型只负责接活和写工作说明，干活交给大模型，本人只做最终批准 |

## 2. 设计原则

1. **手机是唯一的运行主体。** 不买助理号码、不做呼叫转移、不自建电话服务器。联网调用模型服务是允许的。
2. **能力分级，诚实降级。** 每一项能力都有"已验证 / 未验证 / 不支持"三态。未验证的能力默认关闭。
3. **模型负责理解和措辞，代码负责权限和状态。** 任何外发、授权、状态迁移都不交给模型自行遵守。
4. **来电方永远是外部输入。** 语音、短信、邮件、网页内容只作资料，不能改规则，不能获得权限。
5. **不宣称没发生的事。** 运行状态"完成"不等于交付物合格；拿不到的日志不虚构。
6. **复用优先。** 办公能力复用 ChatGPT Work；偏好记忆优先复用 ChatGPT 记忆；手机只留最小可控记录。

## 3. 能力分级与运行模式

### 3.1 三档模式

| 模式 | 设备条件 | 来电时能做什么 |
| --- | --- | --- |
| **L0 标准** | 任意 Android 10+，本应用设为默认拨号应用 | 规则接听/拒接/静音；**拒接后以短信继续对话**并收集需求；未接回拨待办；任务、审批、Work 交接、记忆、档案全部可用 |
| **L1 特权语音** | 本应用以系统特权应用安装（自编 ROM 或 root 后的 priv-app 模块），并通过真机验证向导 | AI 用授权音色**语音代接**、实时对话、同机一键接管或"模拟响铃"接管 |
| **L2 外接音频桥** | 另需蓝牙免提设备等硬件（**需主人单独确认，首版不实现**） | 以蓝牙 HFP 取得通话双向音频，作为无法获得特权时的替代 |

应用启动时运行能力探针，得出当前设备的最高可用模式。规则里写"AI 代接"的条目，在 L1 未验证时自动降级为"短信代办"，并把降级原因写进档案。

### 3.2 为什么 L0 拿不到通话音频

Android 官方文档：通话进行时，只有**持有 `CAPTURE_AUDIO_OUTPUT` 的特权（预装）应用**能用 `VOICE_UPLINK` / `VOICE_DOWNLINK` 或 `TYPE_TELEPHONY` 采集通话音频；无障碍服务在通话中只能采集本机麦克风，拿不到对方声音。默认拨号应用角色能控制通话，但不给音频。所以 L0 只做控制，不做语音对话，也不用免提外放加环境麦克风冒充双向音频。

### 3.3 L1：复用 AOSP 的来电筛选架构

AOSP 源码中有一组系统接口（`@SystemApi`，已在 `frameworks/base` 主干核对），正好是 Android 自己做来电筛选时使用的链路：

| 接口 | 作用 | 要求 |
| --- | --- | --- |
| `Call.enterBackgroundAudioProcessing()` | 把响铃或通话中的来电置入 `STATE_AUDIO_PROCESSING`：网络侧已接通，但**不连接本机麦克风和听筒/扬声器**，音频模式为 `MODE_CALL_SCREENING` | 仅默认拨号应用可调用 |
| `Call.exitBackgroundAudioProcessing(shouldRing)` | 退出处理状态：`false` 直接变为普通通话，`true` 进入 `STATE_SIMULATED_RINGING`，让手机重新响铃 | 同上 |
| `AudioManager.isPstnCallAudioInterceptable()` | 平台是否允许拦截普通电话音频（取决于音频 HAL） | `CALL_AUDIO_INTERCEPTION` |
| `AudioManager.getCallDownlinkExtractionAudioRecord(fmt)` | 取得**对方声音**（下行） | 同上；8–48 kHz，PCM16/Float，单/双声道 |
| `AudioManager.getCallUplinkInjectionAudioTrack(fmt)` | 把合成语音**送入通话**（上行） | 同上 |

L1 的代接流程：

```text
RINGING ──(规则：响铃 N 秒无人接)──▶ enterBackgroundAudioProcessing()
   ▼
AUDIO_PROCESSING（本机麦克风、听筒都不接入）
   ├─ 下行提取 AudioRecord ──▶ VAD ──▶ 流式转写 ──▶ 对话引擎
   └─ 上行注入 AudioTrack ◀── 流式 TTS ◀── 句子切分 ◀──┘
   │
   ├─ 主人点"接管"            ──▶ 停 TTS、清队列、释放音频 ──▶ exit(false) ──▶ ACTIVE（主人直接通话）
   ├─ 触发升级（重要联系人等） ──▶ AI 说"请稍候" ──▶ exit(true) ──▶ SIMULATED_RINGING（手机响铃，主人接起）
   └─ 对话结束                ──▶ AI 道别 ──▶ disconnect()
```

**安全兜底**：AI 会话崩溃、网络中断超过阈值或探针发现音频失效时，看门狗执行 `exitBackgroundAudioProcessing(true)`，把来电交还给主人（响铃），而不是让对方对着一条无声线路。

**必须诚实标注的地方**：

- 这些是隐藏系统接口，需要特权安装加非 SDK 接口访问；不同厂商 ROM 可能删改。
- `isPstnCallAudioInterceptable()` 取决于音频 HAL 是否暴露电话 TX/RX 设备，**同一系统版本在不同机型上也可能不同**。
- `STATE_SIMULATED_RINGING` 之后主人未接时，能否回到处理状态，需要真机验证；未验证前回退为"留言 + 回拨待办"。
- 以上只经过源码核对和模拟器控制流验证，**未经真机双向音频验收**。

### 3.4 L0：短信代办

1. 来电命中"短信代办"规则 → 默认拨号应用拒接，并发送一条披露身份的短信（例如"我是××的 AI 助理，他现在不方便接听。请直接回复短信说明来意，我会整理后转告"）。
2. 为该号码开启 24 小时的短信会话窗口。窗口外的短信一律不自动回复，避免被人利用来刷短信或造成回复循环；也不回复短号码和服务号。
3. 来电方回复 → 同一个对话引擎（文本通道）处理 → 追问、复述确认、创建任务。每个会话最多自动回复 8 条，超出后提示"已转告本人"。
4. 所有短信都进入档案，主人可在应用里看到完整往来并随时接手。

这条通道只需要默认拨号应用角色和短信权限，适用于任何可安装应用的 Android 手机。

### 3.5 能力探针与真机验证

**静态探针**（每次启动运行，无需通话）：系统版本、是否默认拨号应用、是否特权安装、`CALL_AUDIO_INTERCEPTION` / `CAPTURE_AUDIO_OUTPUT` 是否已授予、隐藏接口是否可访问、`isPstnCallAudioInterceptable()`、全屏来电通知权限、短信/通讯录/通知权限、电池优化豁免、网络。

**真机验证向导**（需要另一部手机打进来，由测试者配合）：

| 步骤 | 判定方式 |
| --- | --- |
| 1. 锁屏状态下收到来电 | 自动：`onCallAdded` 且状态为响铃 |
| 2. 进入后台音频处理 | 自动：状态变为 `AUDIO_PROCESSING` |
| 3. 取得对方声音 | 自动：测试者按提示说话，下行 RMS 能量超过阈值且转写出现提示词 |
| 4. 合成声音送入通话 | **人工**：测试者确认听到测试语句（无法从本机自动判定对方听到了什么） |
| 5. 主人接管 | 自动 + 人工：状态变为 `ACTIVE`，双方确认能正常对话 |
| 6. 模拟响铃接管 | 自动：状态经 `SIMULATED_RINGING` 回到 `ACTIVE` |
| 7. 后台、耳机切换、弱网、AI 崩溃恢复 | 人工逐项勾选 |

向导输出一份 JSON 报告，包含 `Build.FINGERPRINT`、各步骤结果和测量值。**只有步骤 1–5 全部通过，本机才会开放 L1 自动代接**；系统更新导致指纹变化后需要重新验证。报告可以提交到仓库的 `docs/CAPABILITY_MATRIX.md`，形成社区兼容矩阵。

### 3.6 iOS 评估

Apple 提供了向通话添加合成语音的能力，但目前没有公开途径让普通应用自动接听运营商来电并取得对方音频。iOS 版暂不实现，只保留平台适配接口；如果将来 Apple 开放相关能力，再按同样的探针与验证流程接入。

## 4. 语音链路

### 4.1 管线与延迟预算

```text
对方说话 ─▶ 下行 PCM(8/16k) ─▶ 客户端 VAD ─▶ 重采样 24k ─▶ gpt-live-transcribe（WebSocket 流式）
                                   │ 静音 ≥ 600ms → commit
                                   ▼
                     最终转写 ─▶ 对话引擎（Responses 流式 + 工具）
                                   │ 按句切分
                                   ▼
               TTS（每句一次流式请求）─▶ 上行 PCM ─▶ 注入通话
```

| 环节 | 目标（P50） | 说明 |
| --- | --- | --- |
| 判定说完 | 600 ms | 静音门限，可调；中文停顿较多，太短会抢话 |
| 最终转写 | ≤ 300 ms | commit 后等待 `...transcription.completed` |
| 首句文字 | ≤ 600 ms | 小模型、推理强度 `none`、短提示词、句子级切分 |
| 首段音频 | ≤ 250 ms | ElevenLabs Flash v2.5 或 OpenAI TTS 的 PCM 流 |
| **合计** | **≈ 1.7 s** | 超过 1.2 s 仍无首句时，先播放预合成的"嗯，好的"类应答 |

判断好坏只看对方实际听到的效果：音色相似度、中文识别、数字读法、端到端延迟。供应商公布的模型耗时只作参考。

### 4.2 语音识别

- 默认使用 OpenAI 实时转写会话：`wss://api.openai.com/v1/realtime?intent=transcription`，`session.type = "transcription"`，模型 `gpt-live-transcribe`，输入格式 `audio/pcm` 24 kHz。
- 官方说明该模型**不支持服务端 VAD**，`turn_detection` 必须为 `null`，由客户端检测说完后发送 `input_audio_buffer.commit`。所以 VAD 在手机端实现（能量 + 过零率 + 挂起时间），参数可调。
- 该模型不返回置信度，"连续听错"改用行为信号判断：对方连续说"不是""听不清""我说的是……"，或助理连续两次请对方重复。
- 通话下行一般是 8 kHz 或 16 kHz，线性插值重采样到 24 kHz。
- 提示词和 `keywords` 里放主人姓名、公司名、常见项目名，提高专有名词识别率。

### 4.3 生成回复

- 默认 OpenAI Responses API 流式输出，模型默认 `gpt-6-luna`，`reasoning.effort = "none"`。可在设置中换成 `gpt-6-sol`，或任何兼容 Chat Completions 的端点（国内兼容服务、本机 ollama / llama-server）。
- `store: false`，对话历史由手机保存并逐轮发送，不依赖服务端会话。
- 文字流按中文句读（。！？；）切句，首句较短时在逗号处提前切出，尽早送去合成。
- 工具调用见第 5 节。

### 4.4 语音合成

| 用途 | 默认 | 说明 |
| --- | --- | --- |
| 本人授权音色 | ElevenLabs `eleven_flash_v2_5`，`output_format=pcm_16000` | 音色由主人在 ElevenLabs 完成克隆和验证，应用只保存 `voice_id` 和授权记录 |
| 普通合成音色（备用、撤销后） | OpenAI `gpt-4o-mini-tts`，`response_format=pcm`（24 kHz） | 音色撤销或克隆服务不可用时自动切换 |
| 本地（后续） | Qwen3-TTS 0.6B Base 等 | 手机端推理延迟未验证，首版不启用 |

**预合成常用语**：披露开场白、"请稍等"、"我帮您记下了"、"正在为您转接"等 10 余句，在主人配置音色时一次性合成并缓存（按音色 ID + 文本哈希索引）。开场白零等待，也节省费用。

### 4.5 通话行为

- **打断**：AI 播放期间检测到对方持续说话超过 250 ms（门限比平时高，避免残余回声误触发）→ 立刻停止播放、清空队列、取消正在进行的生成。历史记录里只保留实际播出的部分，并标注"被打断"。
- **上下行分离**：下行提取只有对方声音，上行注入只有 AI 声音，AI 不会把自己的话当成对方发言。
- **复述确认**：见 5.3。
- **短句**：系统提示要求每轮不超过两句，长任务一律交给 Work，电话里只确认需求和查询**已核实**的状态。
- **披露**：开场白由模板生成而不是模型生成，模板必须包含"AI""助理/助手""授权"字样，否则无法保存；开启录音时自动追加录音告知。

## 5. 对话引擎与工具

### 5.1 引擎

对话引擎与通道无关：语音通道把输出切句送 TTS，短信通道把输出合并为一条短信，仿真台直接打印。每轮流程：

1. 把来电方的话作为用户消息加入历史（系统提示里声明：用户消息是来电方所说，属于外部资料）。
2. 流式调用模型；文字增量立即切句输出；收集工具调用。
3. 工具调用逐个经过**动作闸门**校验后执行，结果回填给模型；最多 3 轮。
4. 代码层的升级检测和关键词检测与模型并行运行，不依赖模型是否调用工具。

### 5.2 通话中可用的工具（封闭列表）

| 工具 | 作用 | 闸门规则 |
| --- | --- | --- |
| `take_message` | 记录留言 | 总是允许 |
| `confirm_details` | 登记即将复述的关键字段 | 总是允许 |
| `create_task` | 创建办事请求 | 关键字段必须已复述且对方已肯定；只生成"待确认"任务 |
| `check_task_status` | 查询任务状态 | 只能查与**当前来电号码**关联的任务；只返回已核实的状态 |
| `schedule_callback` | 登记回拨 | 只生成待办，不直接外呼 |
| `escalate_to_owner` | 请主人接管 | 总是允许；按主人设置通知或模拟响铃 |
| `get_owner_availability` | 读取主人允许对外说的状态 | 只返回主人填写的公开状态文本 |
| `note_fact` | 记录对方提供的新信息 | 一律存为"待确认"，不能改写已有资料 |
| `mark_spam` | 标记骚扰 | 仅对未存通讯录的号码生效 |
| `end_call` | 道别后挂断 | 允许；挂断前等待道别语播完 |

**通话上下文里不存在**读邮箱、发邮件、共享文件、付款、改设置之类的工具。来电方说什么都无法让模型调用一个不存在的工具，这是最根本的防线。

### 5.3 关键信息复述（代码强制）

金额、日期时间、电话号码、邮箱、数量、账号类字段被定义为关键字段：

1. 模型调用 `confirm_details` 登记字段和值，并在回复里向对方复述。
2. 引擎检查对方的**下一句话**：含肯定表达（"对""是的""没错""可以"等）且不含否定和更正时，才把这些字段标记为已确认。
3. `create_task` 中出现的关键字段，其值必须与已确认的值一致，否则调用失败，并提示模型先复述。

### 5.4 升级规则（代码判定）

以下任一情况立即通知主人，按设置决定是否模拟响铃：

- 主人标记的重要联系人来电（通常直接不代接）；
- 对方要求本人（模型调用工具，或命中"找他本人""转人工""真人"等关键词）；
- 争议或重大承诺（"投诉""律师""起诉""违约""赔偿""合同""签字""转账"等）；
- 紧急情况（"急救""出事""医院""报警"等）；
- 身份不明却提出涉及主人隐私或财务的请求；
- 连续两次沟通失败（见 4.2）。

**紧急号码（110/119/120/122/112/911 等）的来电和去电永远不接管、不拦截。**

主人接管后，摘要只显示在主人屏幕上，绝不播给来电方。

## 6. 安全模型

### 6.1 身份

- 来电号码和相似音色**都不能**证明对方是主人。主人的指令只从已解锁的应用界面发出，审批操作还要经过系统生物识别。
- 通讯录联系人只代表"已知"，不代表"可授权"。

### 6.2 动作闸门与审批

```text
模型/来电方 ──只能──▶ 提议（任务、外发草稿）
主人（生物识别）──▶ 审批：对象 + 最终内容 + 附件哈希 ──▶ 审批哈希
执行器 ──▶ 状态比较并交换：APPROVED → EXECUTING（只成功一次）──▶ DONE / FAILED / UNKNOWN
```

- 审批绑定 `SHA-256(规范化 JSON(动作类型, 对象, 标题, 正文, 附件哈希列表))`。内容改动一个字，原审批自动失效。
- 外发动作有唯一的幂等键。执行前在数据库事务里把状态从 `APPROVED` 改为 `EXECUTING`，改不成功就不执行。执行中途崩溃的动作标为 `UNKNOWN`，**不自动重试**，由主人确认实际结果，杜绝重复发信。
- 付款、签约类动作不提供执行器，只生成提醒交给本人。
- 某条执行路径如果无法真正限制外发（例如 Work 代理拥有无审批的发信插件），这条路径不开放无人值守，只允许"Work 生成草稿 → 主人在 ChatGPT 内审批"。

### 6.3 提示注入

- 来电方话语、短信、Work 返回内容、网页摘录，一律用明确的"外部资料"标记包裹后放入模型输入。
- 工具集封闭，权限在代码中判定。
- 评测集包含注入、冒充主人、诱导承诺、索要隐私等场景，每次修改提示词或模型都要跑一遍（见 11.3）。

## 7. 任务与 Work 交接

### 7.1 任务状态机

```text
               主人确认交接            运行开始              API: completed
PENDING_CONFIRMATION ──▶ HANDED_OFF ──▶ IN_PROGRESS ──▶ NEEDS_VERIFICATION ──(核验通过)──▶ COMPLETED
   待确认        │          已交接     │   执行中     ▲       待核实              │          已完成
                │                     ▼             │                         ▼
                ▼                AWAITING_APPROVAL ──┘                      FAILED 失败
            CANCELLED            待审批（suspended）                     （主人可重新交接）
```

**Work 报告"完成"只能把任务推进到"待核实"**。只有结果清单校验通过，或主人亲自核对交付物后，任务才会进入"已完成"。电话里回答进度时，也只报告已核实的状态。

### 7.2 三条交接路径

| 路径 | 条件 | 流程 | 自动化程度 |
| --- | --- | --- | --- |
| **A. Workspace Agents API** | 工作区管理员已启用、主人有访问令牌和已发布代理的触发 ID | `POST https://api.chatgpt.com/v1/workspace_agents/{id}/trigger`，携带任务卡，`Idempotency-Key` = 任务交接键，`conversation_key` = 任务 ID；轮询 `GET .../runs/{run_id}`（请求头 `OpenAI-Beta: workspace_agent_runs=v1`） | 触发和状态自动；**代理回复无法通过接口取回**，交付物走交换目录 |
| **B. 分享任务卡** | 任何 ChatGPT 账号 | 生成任务卡 → 主人确认 → 系统分享面板发给 ChatGPT，或复制文本 → 完成后主人导入交付物 | 需要人工操作，界面明确标注"半自动" |
| **C. 其他官方 API** | 以后需要时单独评估 | 能力、授权、费用逐项核实 | — |

两条始终遵守的规则：不抓取登录 Cookie，不调用未公开的 ChatGPT 接口。ChatGPT 订阅和 API 分开计费。

### 7.3 任务卡 v1

Markdown 正文给人和代理阅读，末尾附一段 JSON 供程序解析：

```json
{
  "schema": "juiz.taskcard/v1",
  "task_id": "T-20260928-0007",
  "handoff_key": "T-20260928-0007#1",
  "title": "为李女士准备 Q3 合作方案 Slides",
  "request": "……来电方原话摘要……",
  "confirmed_fields": {"deadline": "2026-10-08 18:00", "email": "li@example.com"},
  "deliverable": "10 页以内 Slides，中文",
  "constraints": ["不得直接外发邮件；如需外发，生成草稿并等待主人在 ChatGPT 中审批"],
  "result_protocol": {"folder": "Juiz/T-20260928-0007/", "manifest": "result.json"}
}
```

### 7.4 结果清单 v1（`result.json`）

```json
{
  "schema": "juiz.result/v1",
  "task_id": "T-20260928-0007",
  "status": "completed",
  "summary": "已生成 8 页方案",
  "deliverables": [{"path": "q3-plan.pptx", "sha256": "…", "bytes": 482113}],
  "actions": [{"type": "email_draft", "target": "li@example.com", "state": "draft"}]
}
```

手机通过系统文件选择器（SAF）授权访问一个"交换目录"。这个目录可以由代理写入的云盘同步到本机，具体取决于主人的工具，**是否可行需要按账号实测**。手机扫描到清单后逐项核验：`task_id` 一致、文件都存在、SHA-256 和大小都匹配，才标记完成，否则列出不一致项，保持"待核实"。

## 8. 记忆

- 偏好和个人背景优先使用 ChatGPT 已有的记忆；手机不去读取全部 ChatGPT 历史。
- 手机只保存必要的可控记录：联系人备注、已确认偏好、项目状态、未完成承诺。每条记录都带来源（主人 / 来电方 / Work / 系统）、来源引用和更新时间。
- **来电方提供的信息一律先存为"待确认"**，不直接改写已有资料。主人确认后才生效。
- 每条记录有"通话中可引用"开关：只有主人允许的记录会进入通话提示词。
- 支持查看、修改、删除和导出（JSON）。首版只用本地 SQLite，不做知识图谱。

## 9. 档案

### 9.1 时间线与哈希链

每个事件（来电、转写片段、工具调用、任务迁移、审批、外发回执、同意变更）追加写入 `archive_events`：

```text
hash_n = SHA-256( hash_{n-1} ‖ seq ‖ ts ‖ type ‖ ref ‖ 规范化 payload )
```

文件（录音、交付物）只保存路径、大小和 SHA-256，内容放在应用私有目录。AI 总结和原始材料分开存放，总结里注明依据的事件序号。

### 9.2 外部锚定

同机哈希挡不住拥有整机权限的人重写整条链。因此应用每天把链头（`seq` + `hash`）写进每日简报通知，并随加密备份保存到主人指定的外部位置。事后核对时，只要外部留存的锚点和链上一致，锚点之前的记录就没有被改写过。

### 9.3 导出与备份

- **档案包**（zip）：`timeline.html`（无需 ChatGPT 或本应用即可阅读）、`events.jsonl`、`files/`、`MANIFEST.sha256`、`README.txt`（校验方法）。
- **加密备份**：AES-256-GCM，密钥由主人口令经 PBKDF2-HMAC-SHA256（31 万次迭代）派生，写入主人通过 SAF 选定的位置。
- 保留期限与删除规则可配置；删除会写入一条删除事件（只记录被删对象的哈希）。
- 书面确认草稿经主人批准后才发送；对方明确回复才算确认，沉默不算。这些措施提高可追溯性，**不承诺任何特定的法律证明力**。

## 14. V3.1 新增能力

### 14.1 情绪滤网（本人接听）

规则动作 `RING_WITH_SHIELD`：手机正常响铃，本人接起后自动开启滤网（需要 L1 音频路径）。

```text
对方声音 ─┬─▶ 压低音量 + 吼叫削峰 ──────────────▶ 本人听筒（或静音，只听平静复述）
          └─▶ 断句 → 转写 → 词表过滤（立即字幕）→ 模型改写（定稿字幕 / 平静复述）
本人麦克风 ──────────────────────────────────▶ 通话（本人自己说话）
```

- 字幕只保留事实、要求、期限和"对方不满的具体原因"；辱骂与宣泄整句剔除。
- 原话只留在会话内存里，本人点"查看原话"才显示。
- 挂断后生成**去情绪摘要**：要做的事、期限、可改进的点、本人已答应的事、语气强度。
- **不做**：隐瞒身份让 AI 冒充本人挨骂。原因见 13 节与 OpenAI TTS 使用政策、《人工智能生成合成内容标识办法》。

### 14.2 选句代答

滤网中可切换到"选句代答"：本人麦克风不送入通话；对方每说完一句，Juiz 准备三句候选（确认 / 说明 / 缓一缓），本人点选或自己输入，由合成声音（授权后可用本人克隆音色）说给对方。
第一次代答前说一句"我这边不方便说话，用语音助手回复您"——内容是本人决定的，但声音是合成的，按供应商条款与标识办法需要标识。

### 14.3 深夜代办（授权白名单）

主人事先为某个联系人设置 `ErrandGrant`：时段、可外发文件夹、**预先登记的收件邮箱**、每日上限、可告知的资料。
- 工具 `list_authorized_files` / `send_authorized_file` / `lookup_authorized_info` 只在授权时段内出现；
- 收件地址由系统决定，对方口头给的新地址一律不用；
- 发送走外发动作：以授权 ID 作为审批来源、绑定文件哈希、单次执行、留档；
- 资料检索由代码完成（字二元组重合度），命中的资料直接附给模型，不依赖小模型想起去查。

### 14.4 执行方：谁来干活

| 路径 | 说明 | 自动化 |
| --- | --- | --- |
| **云端大模型（默认）** | 手机直连 OpenAI Responses 后台模式 + 代码沙箱，默认 `gpt-6-sol`；手机轮询、下载成品、自己算哈希 | 全自动，按 API 计费 |
| ChatGPT App（Work 模式） | 系统分享把任务卡带进 App；可选实验性"辅助点按"只在发起后 60 秒内切到 Work 并发送，不读回答 | 半自动 |
| Workspace Agents API | 企业工作区，已实现 | 触发与状态自动；回复取不回 |
| 电脑上的 Codex（可选） | `juiz-desk` 监听同步目录，`codex exec -m gpt-6-sol`，沙箱内只产出文件和草稿，默认关闭应用连接器 | 全自动 |

共同约定：任务卡里有通话侧写的**工作说明（brief）**；执行方只产出 `out/` 文件和 `drafts/*.json` 邮件草稿；
手机核验哈希后把草稿变成待审批的外发动作，**本人指纹确认后才发出**，附件发送前再校验一次哈希。

### 14.5 小模型的代码层兜底

评测中发现小模型（qwen3.5:9b）会：忘记调用工具、把复述确认做一半、谎称"已发送"、漏出 `<invoke>` 之类标签、给机主加"先生"。对应的兜底全部在代码里：

| 问题 | 兜底 |
| --- | --- |
| 复述后忘记建任务 | `create_task` 遇到未确认的关键信息时**先挂起**；对方下一句肯定后由引擎自动创建 |
| 不调用 `confirm_details`，直接在话里复述并发问 | `ConfirmationTracker.observeAssistantUtterance`：从 Juiz 自己的问句里抽出邮箱、电话、时间、金额，登记为"待确认"，对方肯定照样算确认 |
| 对方确认后仍不建任务（只给一个工具也不调用，真机实测） | **补登记**：单独请模型只输出一个 JSON（是不是办事请求、标题、请求），由代码拼出 `create_task`，字段值直接用对方确认过的原值；JSON 解析不出就用对方原话建任务。结果记入档案（`guard.task_rescue`） |
| 没发却说"已发送/办好了" | `ClaimGuard`：本轮没有对应工具成功时，替换成"这个我需要确认后再告诉您"，并记入档案 |
| 没建任务却说"已受理/提交了请办任务/任务已确认创建" | `ClaimGuard` 按分句判断：同一分句里有"任务"类名词 + 登记类动词 + 已然标记、且没有"会/将/确认后"之类将来时，就算声称任务已建立；没有真建任务时换成"您的要求我会完整转告本人，由本人确认后处理" |
| 伪标签、Markdown | 说出口前清理 |
| 给机主加称谓 | 按机主名字和姓氏去掉"先生/女士/小姐" |

### 14.6 音频链路的修正（来自音频测试台）

用本机 Qwen3-TTS 生成领导/同事/客户语音、降成电话音质，按真实时间喂给语音代码，发现并修正：
- **断句被自然停顿切碎** → `UtteranceJoiner`：说完后按结尾标点与长度自适应宽限 350–900 ms，对方接着说就继续拼；
- **AI 说话时对方的话被丢** → 两个 VAD：断句/转写始终用正常门限，是否打断 Juiz 另用高门限；
- **噪声底被说话声抬高** → 最小值统计估计噪声底；下行加慢速自动增益（只用于断句和转写）。

### 14.7 伙伴 Juiz

首页的小人有 8 个表情，会眨眼、浮动、被点会跳；台词与表情由配置的模型根据"此刻的情况"（时间、待办、昨夜代办、是否在通话）生成，只能引用给定的事实；模型不可用或超时则用预设台词。默认称呼使用者为"伙伴"，可在「我的资料」里修改；对来电方介绍时使用机主名字。

### 14.8 原通话回放与核对

确认一件委托之前，本人可以回到"原话"核对：

- **录音**：只在本人打开「通话录音」同意时录（开场白会告知对方）。录音器挂在通话音频端口上：左声道是对方（下行），右声道是 Juiz（上行）。时间线按真实经过的时间对齐：Juiz 的语音按"开始播放的那一刻"排进去；下行中断超过 0.3 秒就补静音（音频测试台里发现：按采样数计时会把一分钟的通话压成十几秒）；被打断清空缓冲时，没播出去的部分从录音里截掉——录下来的就是对方实际听到的。
- **保存**：通话结束后混成立体声 WAV，用 Keystore 里单独一把不可导出的 AES-GCM 密钥加密，存在 no-backup 目录；明文的 SHA-256 写进哈希链档案（`recording.saved`）。
- **回放**：委托详情页「原始来电」→ 指纹/锁屏密码确认 → 解密到内存（不落盘）播放；每次回放都重算哈希与档案比对，显示"与档案一致"或"可能被改动"，并记入档案（`recording.played`）。
- **短信**：短信代办的委托直接显示往来原文；语音通话同时可展开转写原文（受「转写留存」同意约束）。
- **删除**：默认 30 天后自动删除；撤销录音同意时立即删除全部录音；删除都记入档案（`recording.deleted`）。
- **本人接听（情绪滤网）不录音**：那时没有开场白告知对方。
