## 通话音频测试台

用本机 Qwen3-TTS 生成的领导/同事/客户/诈骗/家人语音，经过电话线路模拟（8 kHz、300–3400 Hz、μ-law、底噪），
按真实时间喂给 `VoiceSession` / `ShieldSession`。转写用本机 Qwen3-ASR，对话模型用本机 qwen3.5:9b，Juiz 的声音用本机 Qwen3-TTS。

**测试台发现并已修复的问题**：
1. 自然停顿把一句话切成几段，Juiz 回答半句话 → 断句拼接（自适应宽限期）。
2. AI 说话时，对方的话被高门限丢掉（家人急事的关键半句丢失）→ 断句与打断用两个 VAD。
3. 噪声底被说话声抬高，整句被判成安静 → 最小值统计噪声底 + 自动增益。
4. 英文句点把邮箱地址切开朗读 → 句点后面有空白才算句末。
5. 小模型把"只有情绪"判断错，丢掉了事实 → 词表保留了内容时不许替换成"只有情绪"。
6. Juiz 把提示词里的"（不超过25字）"念了出来（本机合成还因此卡住）→ 说出口前去掉这类写作要求。
8. Juiz 把工具名放在括号里念出来（"（take_message）需要您回电吗？"）→ 说出口前去掉括号里的工具名、参数名。
9. 小模型把留言参数写成 JSON 念了出来（"```json" "\"summary\": ……"）→ 这类文本不念；认得出的工具调用（留言、建任务）照样执行。

**通话录音核对**（2026-09-29，同事来办事一通）：左声道转写与对方原话字错率 7.3%，右声道与 Juiz 说的话 8.0%，对方两句话在录音里的位置与真实开口时刻误差都在 1.5 秒内。
深夜代办一通里 Juiz 被插话打断，没播出去的半句正确地没有出现在录音里；挂断之后对方说的话也不在录音里。

注意：本机同时跑对话模型、语音合成和识别三个模型时内存吃紧（出现大量换页），会出现模型超时、合成慢到几十秒——这时的延迟数字不代表云端链路，结论要在空闲时跑。
7. 通话录音的时间线被压缩（测试台里对方不说话时不送下行帧，按采样数计时，一分钟的通话录成 14 秒）→ 按真实时间对齐，下行中断补静音。

结果与各环节耗时见下方"最近一次运行"。本地三模型同时在 16 GB 内存上运行，**延迟不代表云端链路**（gpt-live-transcribe + 小模型 + 流式 TTS）。
