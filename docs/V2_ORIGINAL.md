# 手机原生 AI 助手：复用 ChatGPT Work 的轻量架构

> 版本：V2，2026-09-28。供实现型 AI 使用，以本版替代上一版的服务器中心架构。
> 本文明确产品目标与实现边界。引用的是已核对的官方资料，尚未进行真机或账号集成测试。

## 1. 产品目标

做一个安装在主人手机上的开源助理。别人拨打主人原来的手机号，手机按主人设定的规则接听。AI 理解对方的话，通过本人授权的克隆音色回答。收到办事请求后，优先交给 ChatGPT Work 与已有插件完成。

**默认不购买助理号码，不使用呼叫转移，不自建电话服务器，不开发独立电脑执行器。** 电话仍通过手机原来的 SIM 和运营商线路接入。项目主要开发手机端的连接层，尽量复用现成的模型与办公能力。

“不自建服务器”允许手机联网调用 OpenAI 或语音供应商。需要访问电脑本地文件时，可选接入官方已有的远程能力；这不作为首版前提。完全离线运行另列为后续目标。

## 2. 核心架构

```text
对方拨打主人原手机号
        ↓
手机原生电话与通话音频适配层
        ↓
语音识别 → GPT 生成回复文字 → 本人授权音色 TTS
        ↑                                ↓
        └──────── 双向电话音频 ──────────┘
                      │
                手机端助理控制层
                      │
          ┌───────────┼────────────┐
          ↓           ↓            ↓
    Work 任务交接   主人审批与接管   本地记忆与档案
          ↓
  ChatGPT Work / 获授权的工作区代理
          ↓
  现有插件办理邮件、资料检索、Slides 等任务
```

这是一张目标架构图。手机音频接入与 Work 交接都必须先通过能力验证，不能把箭头当成现成接口。

### 自己开发与直接复用的边界

| 能力 | 处理方式 |
| --- | --- |
| 手机来电控制、通话音频、同机人工接管 | 自己做平台适配，这是项目的主要技术难点。 |
| 语音识别、文字理解、克隆语音 | 接成熟模型。提供可替换接口，不训练大模型。 |
| 邮件、Slides、资料检索、办公任务 | 优先复用 ChatGPT Work 与已授权插件，按账号实际能力启用。[1] |
| 偏好记忆 | 优先复用 ChatGPT 已有记忆；另保留必要的本地事实与任务记录。[9] |
| 授权、任务关联、可靠留档 | 手机端保留最小实现，不依赖模型自行遵守。 |

首版用一个原生手机应用承载控制逻辑。本地数据库保存任务状态，文件目录保存档案。暂不建设微服务、插件市场或独立办公代理平台。

## 3. 第一优先级：打通原生电话

### 必须分别验证三个能力

“发现来电并接听”“实时取得对方声音”“把合成声音送入通话”是三个独立问题。能点击接听按钮，只完成了其中一个。

Android 可以通过默认拨号应用角色和 `InCallService` 管理电话；官方文档同时说明，读取 `VOICE_CALL` 通话音源需要系统组件权限，普通第三方应用无法直接获得。因此，默认拨号器权限本身不解决双向音频接入。[2][3]

iOS 官方已经提供向通话添加合成音频的相关能力。它不能单独证明普通应用已经具备“自动接听、取得对方音频、无人值守双向对话”的完整链路。iOS 适配需要逐项核实，不能笼统宣称全部不支持，也不能承诺安装即用。[4]

### 首版实施路线

建议先选定一款 Android 测试设备，验证原生电话控制。双向音频优先寻找厂商允许的接口或合法的系统集成方式。系统签名、定制系统或开发机上的特权实验都必须明确标注，不能当作所有手机都能安装使用的普通应用方案；获得特权也不代表硬件音频路径一定打通。

无障碍自动点击只作为界面操作补充。不要把它当成通话音频权限的替代品。手机播放出声音也不等于来电方能听到。

目标设备不支持时，明确报告缺少哪项能力。可另行提出外接通话音频桥作为备选，但它增加了硬件依赖，必须单独确认，不能悄悄改变“手机单机运行”的产品要求。首版也不要用免提外放加环境麦克风冒充可靠的双向音频接入。

**先做真机验证，再做完整产品。** 必须实测锁屏来电、后台运行、耳机切换、弱网，以及 AI 停止后恢复正常通话。没有验证通过的设备应禁用自动代接。

## 4. 语音：GPT 写文字，克隆模型说出来

采用用户指定的链式方案：流式语音识别 → GPT 文字回复 → 流式克隆 TTS。OpenAI 官方也提供这种分阶段语音架构，适合独立替换音色模型或检查中间文字。[5]

### 模型选择

首版优先接成熟的托管语音服务，避免为了 TTS 再建设电脑后端。可以用 ElevenLabs 的授权音色测试 Flash v2.5 或 v3 Conversational，具体模型与所选音色的兼容性以实际测试为准。[6]

开源本地候选可保留 Qwen3-TTS Base，例如 0.6B Base。官方模型卡支持样本音色克隆，但其示例采用 GPU 推理，不能由此推断普通手机能低延迟运行。手机端推理需另做适配和性能验证，首版不强制实现。[7]

选择标准是对方实际听到的效果：本人音色相似度、中文识别、数字读法、完整链路延迟。不要只比较供应商宣传的模型耗时。

### 通话行为

对方插话时立即停止旧音频播放，取消尚未播出的回复。上下行音频分离处理，避免 AI 把自己的声音重新当成对方发言。金额、日期等关键信息应复述确认。

实时回复使用短句。制作 Slides 等长任务交给 Work，电话侧只确认需求与查询已核实的状态。没有结果时不能声称已经完成。

音色必须由本人授权。保留撤销入口与普通合成音色备用。开场明确是受授权的 AI 助手，避免让对方误以为本人正在说话。录音、转写留存和音色使用分别管理授权，不把其中一项同意当成全部同意。

## 5. 办公：优先利用 ChatGPT Work

### 5.1 复用已有办公能力

官方文档说明，Work 可以利用文件、插件和获准工具完成任务，也提供制作演示文稿的使用场景。具备相应选项时可以选择云端执行；涉及本机文件或应用时使用本地执行。[1]

因此，首版把邮箱访问和办公文件生成放在用户已经配置好的 Work 环境里。手机应用只组织任务说明、携带获准的上下文、交接任务、展示审批和归档结果。每个邮箱插件的读写权限都按实际账号验证，不能默认所有连接器都支持发送邮件。

若以后确实需要操作主人的电脑，优先评估官方 Remote。它已有通过手机连接电脑、发起任务和审批的能力，但仍要求目标电脑保持在线与唤醒，且受开放范围和工作区设置影响。官方界面可用也不等于第三方应用已获得相同的自动调用接口。[8]

### 5.2 实时文字回复与 Work 任务交接分开

| 通道 | 负责什么 | 接入原则 |
| --- | --- | --- |
| 电话对话通道 | 听懂来电、生成下一句回答、整理需求 | 使用有正式程序接口的 GPT 文字能力，配合独立 ASR 与 TTS。 |
| Work 办事通道 | 制作文件、处理邮件、执行较长工作 | 优先使用账号可用的官方任务入口，复用已有工具与审批。 |

不能假设个人 ChatGPT 界面的所有功能都已变成可供外部程序调用的接口。GPT API 也不能默认继承 ChatGPT 中已经登录的邮箱、插件或全部记忆。

目前已核实的自动交接选项是 **Workspace Agents API**。它可以触发已发布的工作区代理，也提供测试阶段的运行状态查询；官方文档仍明确说明，代理回复目前不能通过该接口直接取回。它是有明确适用范围的工作区接口，不能等同于任意个人 Work 会话的通用接口。[10]

该接口还需要工作区管理员启用相应权限并允许创建访问令牌。实现前先验证用户账号是否具备资格。[11]

### 5.3 根据真实接口选择交接方式

**具备官方触发能力时：** 手机发送带任务编号的结构化说明。若代理具备相应写入工具，可让它把交付物与简短结果清单保存到用户指定的已授权目录。手机通过供应商正式接口或系统文件服务读取，完成验证后归档。这条结果回传路径需要单独测试，不能假设触发接口会返回文件。

**只有 Work 界面可用时：** 手机生成任务卡，由主人确认后交给 Work。使用经核实的分享入口；没有正式入口时提供可复制任务文本。完成后主人确认并导入交付物。明确标注办公交接需要人工操作，不能把它称为全自动版本。

**需要更完整的程序化办公接口时：** 再评估 OpenAI 的其他官方 API。它们的能力、授权与费用单独核实。不要为维持“全部复用 Work”的说法，偷偷抓取登录 Cookie、调用未公开接口或绕过平台审批。

ChatGPT 订阅与 OpenAI API 分开计费。实时对话采用 API 后，不能假设相关费用已包含在订阅中。[12]

## 6. 手机端应保留的功能

### 电话与主人接管

提供按联系人、时段、响铃等待时间配置的代接规则。支持主动拨号、留言、回拨待办和骚扰标记。外呼使用主人真实线路，限制每日次数；服务失效时恢复正常人工通话路径。

重要联系人、对方要求本人、明显争议、重大承诺、身份不明或连续听错时，立即通知主人。默认在同一部手机上接管：停止 AI 发言，清空待播放声音，切回主人使用的麦克风与听筒。摘要只在主人界面显示，不能播放给来电方。

不要向正在通话的本机号码回拨来实现转人工。转到另一台设备需要额外验证运营商或设备能力；未打通时退回留言与回拨安排。

### 任务与授权

保存最小任务状态：待确认、已交接、执行中、待审批、已完成、失败、待核实。关联原始来电、Work 会话与交付物。重复触发或网络重试不能导致重复发信。

来电方只能提出请求，不能授予访问主人邮箱的权限。主人的授权在已登录设备上完成。发邮件、共享附件等操作应绑定具体对象和最终内容；付款、签约等重大动作交给本人。优先复用 Work 自带的审批机制。若某执行路径无法真正限制外发行为，就不启用该路径的无人值守权限。

外部语音、邮件和网页都作为待处理资料，不能修改系统规则。权限限制不能只写在提示词里，也不能仅凭来电号码或相似音色判断对方是主人。

### 主动服务

补充未完成承诺提醒、重要信息通知和每日摘要。能通过 Work 已有功能完成的任务优先复用；新增渠道逐项接入。不要默认手机能跨应用读取所有消息。

## 7. 长期记忆与长期留档

### 记忆：帮助下一次办事

偏好与个人背景优先使用 ChatGPT 已有记忆设置。官方文档区分 ChatGPT 记忆与本地 Codex 记忆；Work 使用账号及工作区可用的记忆设置，不能假设不同运行环境自动共享一份完整历史。[9]

手机只保留必要的可控记录，例如联系人、已确认偏好、项目状态、未完成承诺。每条记录带来源与更新时间。通话模型和 Work 之间通过任务卡传递必要信息，不默认读取全部 ChatGPT 历史。

支持主人查看、纠正、删除和导出。来电方提出的新信息先标记待确认，不能直接改写敏感个人资料。首版使用本地数据库即可，不建设复杂知识图谱。

### 档案：解释当时实际发生了什么

把每次来电和后续工作串成一条时间线。在取得所需授权的范围内保存原始请求、带时间定位的转写、具体审批、交付物及实际可取得的发送回执。录音按适用规则单独启用，AI 总结与原始材料分开保存。

Work 内部操作记录能取得多少，就如实保存多少。拿不到完整日志时，明确标注记录范围，只归档已有任务说明、审批和结果，不虚构全部过程已经留痕。运行状态显示完成也不能替代对交付物的核查。

采用追加式日志、文件版本和哈希清单。加密备份到主人指定的独立位置，支持导出无需 ChatGPT 即可阅读的档案包。只有手机内的一份日志不足以应对设备丢失；只有同机哈希也不足以防止拥有整机权限的人重写记录。

重要事项可生成书面确认草稿，经主人批准后发送。保留对方明确回复，不将沉默视为确认。设定保留期限与删除规则；这些措施提高可追溯性，不承诺自动获得特定法律证明力。

## 8. 开源范围与实施顺序

开源手机应用、平台适配接口、提示词、任务协议和测试用例。供应商账号、私人音色与个人数据不进入仓库。项目代码开源不代表 ChatGPT 或托管语音服务开源。

个人自用版本由用户配置自己的合法凭证，使用系统安全存储。不要在发布包里嵌入共用密钥。公开分发版要核实供应商允许的客户端鉴权方式；若确实需要令牌签发或中转服务，应明确列为额外依赖。

### 第一阶段：两个先行验证

**电话验证：** 在一款明确的设备与系统版本上，实现真实原号码来电接听、对方语音识别、合成声音回传、主人同机接管。不能用应用内语音聊天室或模拟电话替代这项验收。

**Work 验证：** 在目标账号上，验证一项办公任务从交接到获取交付物的全过程。逐项标记自动完成、需要人工确认或暂不支持，不假设接口存在。

### 第二阶段：跑通最小闭环

客户拨打主人手机 → AI 披露身份并确认需求 → 创建任务 → 通过已验证方式交给 Work 制作 Slides → 主人审核外发对象与附件 → 通过已授权工具发送 → 核实结果 → 更新待办与本地档案。

### 第三阶段：逐步减少人工步骤

增加授权克隆音色、多联系人策略、重要消息提醒和记忆管理。根据真机测试扩展机型。再评估本地 TTS 与官方远程电脑能力。

**给实现型 AI 的最终要求：以手机为中心，优先复用 GPT 已有能力。先验证电话音频与 Work 接口，再扩展功能。遇到平台缺口时准确指出限制，不虚构 API，不自行改回服务器电话架构，不把模拟成功写成真实验收通过。**
